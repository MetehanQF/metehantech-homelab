Deployed 2026-09-21 on the Raspberry Pi 5 (`<primary-node>`).

> **State: tested, NOT the home network's DNS yet.** The router at <ROUTER_IP> still
> hands out itself as DNS over DHCP. Nothing resolves through AdGuard unless a client is
> pointed at it manually. See "Going whole-home" below.

## Two things to know before you change anything

**1. `systemd-resolved` must stay running.** Home Assistant runs with host networking and
resolves through `127.0.0.53`; every Docker bridge container resolves through
`127.0.0.11`, whose upstream is that same stub. The usual "free port 53 by disabling
systemd-resolved" advice would break Home Assistant, Frigate, Nextcloud and Mosquitto
simultaneously. It is not needed — resolved binds loopback only, so AdGuard has
`<PRIMARY_NODE_IP>:53` and `<PRIMARY_NODE_TAILSCALE_IP>:53` entirely to itself.

**2. First launch needs root, later launches do not.** AdGuard refuses its very first
start as a non-root user. The initial config was generated by a throwaway root container,
the files were chowned to 1000:1000, and the permanent service runs unprivileged. If you
ever delete `conf/AdGuardHome.yaml`, you have to repeat that dance — `docker compose up`
alone will crash-loop with *"this is the first launch … you must run it as administrator"*.

Related: the shipped `AdGuardHome` binary carries `cap_net_bind_service` as a **file**
capability, so a completely empty capability bounding set makes `execve()` itself fail
with `operation not permitted`. That is why `NET_BIND_SERVICE` is added back.

## Re-applying the production settings

```bash
cd <repo>/dns/adguard
docker compose down
python3 configure.py      # idempotent; keeps AdGuard's own schema and the bcrypt hash
docker compose up -d
```

## Going whole-home (needs your explicit approval — not done)

Set the router's DHCP "DNS server" to **<PRIMARY_NODE_IP>** and renew leases. Do it while you
can physically reach the router. To undo, set DNS back to automatic / `<ROUTER_IP>`.
Before doing it, consider giving the Pi a DHCP reservation for <PRIMARY_NODE_IP> — the lease is
currently dynamic, and if the Pi's address changed while it was the network's only DNS
server, the whole house would lose name resolution.

## Rollback

`docker stop metehantech-adguard` — that is the entire rollback. Full detail in
`workspace/dns-center/RECOVERY.md`.

## Running the Control Center test suite

`pytest` is deliberately **not** installed in the production `.venv`. Recreate a throwaway
one when you need it:

```bash
python3 -m venv /tmp/mt-test-venv
/tmp/mt-test-venv/bin/pip install pytest -r <status-repo>/requirements.txt
cd <status-repo> && /tmp/mt-test-venv/bin/python -m pytest tests/ -q
```

The DNS tests use fixtures only, so they pass whether or not this container is running.
